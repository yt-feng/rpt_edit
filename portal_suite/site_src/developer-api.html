从开通到第一次读取

  1. 开通内容权限。联系 info@kcdesk.com，确认报告范围、可用操作与有效期。
  2. 生成自己的密钥。登录后在「我的账号 → 开发者 API」填写用途名称，例如“内部研究库”，生成并当场保存完整密钥；完整密钥只显示一次。
  3. 保存在服务端环境变量中。下面示例使用 KCD_API_KEY；通过 Authorization: Bearer 请求头鉴权。密钥不要写进公开代码、URL 或网页前端。
  4. 先获取报告 ID，再读取关联内容。从列表取得 id，接着调用详情、PDF 或关联内容接口。所有 ID 都应使用返回值。
GET/reports?limit=25reports:read

02 / REPORT SCHEMA

先看清楚，一份报告有哪些字段

从标题、机构和日期，到 PDF 可用性、过程稿更新时间以及文件校验信息，每个字段都有明确用途。

GET/reports/{id}reports:read

报告列表中的每个 items[]，与单份报告详情的 report 使用同一套字段。下面列的是当前实际返回的数据；空字符串与可选字段有单独说明。

报告元数据：11 个当前字段
字段类型 / 返回条件说明与用途
idstring · 必有稳定的报告标识。用于关联 PDF 和关联内容；作为字符串原样保存，不从标题或文件名自行推导。
titlestring · 必有报告主标题。适合作为资料库中的默认展示名称。
title_zhstring · 必有已有中文标题；没有时返回空字符串。可以回退使用 title。
title_enstring · 必有已有英文标题；没有时返回空字符串。它表示标题，不表示一定存在英文全文。
institutionstring · 必有研究机构名称；未知时可能为空字符串，便于在你的系统里按机构归类。
datestring · 必有报告记录日期，通常为 YYYY-MM-DD，未知时为空字符串。列表的 date 参数按此字段筛选。
page_countinteger · 通常返回非负页数。0 表示当前记录没有可用页数，不能据此判断 PDF 是空文件。
pdf_listedboolean · 必有当前目录是否列有原报告 PDF。true 仍需在下载时核对授权与文件可用性。
sourcestring · 必有catalog 为报告目录记录；processed 为单独发布的过程稿记录。
processed_updated_atstring · 可选有过程稿发布记录时提供的更新时间，通常为 ISO 8601 UTC 时间。可作为你定期复查关联内容的线索；不是独立的增量查询参数。
pdf_availableboolean · 条件返回当前在 source=processed 时返回 false，表示该记录不提供原报告 PDF；目录记录中通常省略此字段。

如何把报告关联到具体文件？

使用 GET /reports/{id}/artifacts，返回的每一项描述一份可读取的文件。文件描述与文件正文分开：列表先告诉你“有什么”，下载接口再返回实际字节。

关联内容描述：10 个字段
字段类型 / 返回条件说明与用途
idstring · 必有关联内容 ID。与 report_id 一起确定下载地址，不应假设每个 ID 都是哈希。
report_idstring · 必有所属报告 ID，用于在你的资料库中建立关联。
kindstring · 必有text / image / chart / metadata / translation / article / pdf 七种材料类别。
languagestring · 必有材料的语言，例如 zh、en；und 表示未标明语言，并非英文。
mime_typestring · 必有文件格式，例如 text/markdown、application/json 或 image/jpeg。
sizeinteger | null · 必有文件字节数。部分索引图表在列表中返回 null；下载响应会给出实际 Content-Length。
filenamestring · 可选建议保存的文件名。保存前仍应在你自己的程序中处理重名；不要仅用它作为唯一标识。
sha256string · 可选64 位十六进制文件校验值，可验证完整下载。已发布的静态材料通常提供；动态生成的说明、索引图表和节选不保证提供。
text_scopestring · 可选文本范围标识。partial_excerpt 明确表示节选；字段缺失也不应直接当作“已确认完整全文”。
page_numberinteger · 可选协议预留的可选字段，当前发布内容的页码主要位于 figure-metadata.json 的 images[].page_number 中，不能依赖文件描述直接提供。

文件 id 是下载接口使用的标识，与文件内容的 sha256 校验值不同，请直接使用列表返回的 ID，不自行推导。

03 / CHARTS & IMAGES

获得图像，也获得理解图像的线索

把图表图片与已有的主题、趋势和报告来源一起带入自己的工作台。

CHART

已索引的图表

kind=chart 返回已索引图像，通常为 JPEG。对应的 JSON 描述可包含图表标题、趋势、指标名称、实体、时间范围、地区及单位。

IMAGE

解析保留的图片

kind=image 返回已发布的图片文件，可为 PNG、JPEG 或 WebP。源页码、像素大小与位置说明可能位于单独的过程稿元数据中。

获取图像与描述的顺序

  1. 按 kind=chart 或 kind=image 获取文件列表。
  2. 通过列表返回的 id 下载图像。按 kind=metadata 读取相关 JSON 文件。
  3. 用 JSON 内的 image_id 或 filename 关联图片；需要源页定位时，查看「过程稿元数据」。
cURL · 查找图表文件
curl --fail-with-body \
  -H "Authorization: Bearer $KCD_API_KEY" \
  'https://kcdesk.com/api/content/v1/reports/REPORT_ID/artifacts?kind=chart&limit=25'

图表索引 JSON：除了图片，还能获得什么？

kind包含什么常见文件与含义

语言、文本范围与文件名怎么配合使用？

如何判断拿到的文本
字段类型 / 返回条件说明与用途
language=zh / en明确语言分别表示中文与英文材料。筛选值应优先取自实际列表，其他语言是否可用取决于已发布产物。
language=und未标明语言解析原文和部分图片常使用该值。第一次查询可以不加语言筛选，避免漏掉可用材料。
text_scope=partial_excerpt明确为节选例如 extracted-text。适合预览或索引，不应保存为“完整原文”。
filename区分具体材料同一 kind=text 可能包含解析文本或播客脚本；应结合文件名辨别用途。
mime_type选择读取方式text/markdown 与 text/plain 读取为文本；application/pdf 按二进制保存。

保留 Markdown 中的图片关联

已发布的 Markdown 图片引用会使用对应交付文件名。按报告 ID 建立本地目录，再把相关 Markdown 与图片保存到同一目录，通常就能保留图文关系；具体文件清单以关联内容列表为准。

05 / PROCESS METADATA

让资料有来源、有位置、有上下文

了解图像来自哪一页、有哪些标题脚注，以及译文与源图如何对应。这些字段帮助你在自己的系统里组织和展示资料。

使用 kind=metadata 列出 JSON 材料，再下载对应文件。这里列出可公开的结构：报告说明、图表描述、源页面与图片定位、译文图片映射，以及解析与翻译说明。不同记录可能只有其中一部分。

cURL · 列出结构化说明文件
curl --fail-with-body \
  -H "Authorization: Bearer $KCD_API_KEY" \
  'https://kcdesk.com/api/content/v1/reports/REPORT_ID/artifacts?kind=metadata&limit=25'
元数据文件地图
材料常见文件名可获得的信息
报告元数据 JSON{report_id}.json与「报告字段」的 Report 对象一致，文件正文不包裹 ok/report。
已索引图表描述{image_id}.json包含图表标题、指标名称、趋势等，详见「图表与图片」。
源页面与图像定位figure-metadata.json包含 records、pages、images 三组结构。
译文图片映射translation-figures.json连接原始图片占位标记与实际交付文件名。
解析 / 翻译说明processing-metadata.json 或 translation-metadata.json包含提取来源、已有翻译语言、翻译提示和未翻译单元数量。

源页面与图像定位

figure-metadata.json 的三组数组分别描述内容块、源页与图片。可按页码和图注辅助理解关系；records 与 images 没有直接逐项映射，不能假定一一对应。嵌套字段仅在来源已有有效值时提供，数组可能为空。

figure-metadata.json：顶层与页面 / 图像字段
字段类型 / 返回条件说明与用途
records[]object[]提取出的图像、表格、标题、文本等记录，字段见下表。
pages[].page_idxinteger从 0 开始的源页面索引。
pages[].page_sizenumber[2] · 可选来源提供的页面尺寸；不要默认与图像像素尺寸使用相同单位。
pages[].text_blocks[]object[] · 可选页面中的文本块或其他结构块，使用与 records[] 相同的字段集合。

从单次读取，到自己的同步流程

每个接口都使用同一基础地址与 Bearer 密钥。下面的 cURL 和 Python 例子可以直接作为接入起点。

五个接口，一套读取流程

响应如何处理

  • 列表与详情返回 JSON。next_cursor: null 表示本次分页结束；items: [] 不是服务错误。
  • 文件接口返回二进制或文本正文，不是带下载链接的 JSON。先检查 HTTP 状态，再保存文件，避免把错误 JSON 保存成 PDF。下载的元数据 JSON 直接是文件内容，不额外包裹 ok 字段。
  • 文件响应包含 Content-Type、Content-Length、Content-Disposition；部分文件还含 ETag。列表中的 sha256 可用于下载后的内容校验。
  • 同一报告记录日期后续可能补入材料。定期复查近期日期并按报告 ID、关联文件 ID 和可选校验值去重，可避免重复保存；游标不是永久同步水位，也不代表固定不变的目录快照。报告按日期与 ID 倒序排列；关联文件按 ID 倒序排列，并非源报告的页码顺序。
Python · 按日期分页，查找已有英文译文
# Python 3 标准库。先在服务端环境变量中设置 KCD_API_KEY。
# 这个例子只遍历目录，不会自动下载整批文件。
import json
import os
import urllib.parse
import urllib.request

BASE = "https://kcdesk.com/api/content/v1"
TOKEN = os.environ["KCD_API_KEY"]

def get_json(path, params):
    query = urllib.parse.urlencode(params)
    request = urllib.request.Request(
        BASE + path + ("?" + query if query else ""),
        headers={"Authorization": "Bearer " + TOKEN},
    )
    with urllib.request.urlopen(request, timeout=30) as response:
        return json.load(response)

def pages(path, params=None):
    params = dict(params or {})
    params["limit"] = 100
    while True:
        payload = get_json(path, params)
        yield from payload["items"]
        cursor = payload.get("next_cursor")
        if not cursor:
            break
        params["cursor"] = cursor

for report in pages("/reports", {"date": "2026-10-08"}):
    print(report["id"], report["title"])
    path = "/reports/" + report["id"] + "/artifacts"
    for item in pages(path, {"kind": "translation", "language": "en"}):
        print("  ", item["id"], item.get("filename"), item["mime_type"])

例子适合先跑通接入。实际长期同步时，请增加请求间隔、失败记录和有限重试，并按下一个页签中的错误码处理授权与额度问题。

接入时常见的几个问题

列表能看到报告，为什么下载不一定成功？

列表描述的是可见记录。下载时仍会重新检查当前授权、会员或试用权限、文件是否可用，以及账号剩余额度；请始终检查下载响应的 HTTP 状态。

查询某种语言得到空列表，是什么意思？

当前报告没有可返回的该语言材料。可以先去掉语言筛选查看实际列表；und 是未标明语言，不能视为英文。

怎样按天更新自己的资料库？

遍历目标日期的报告，再遍历每份报告的关联文件；在自己的系统中按 ID 与可选 SHA-256 去重。近期日期可以重复复查，以发现补发的材料。当前没有“自某更新时间之后”的查询参数或推送订阅。

能通过这个 API 发起 AI 研究或即时翻译吗？

目前这里提供已授权内容的读取与下载。AI 研究仍使用网站现有入口和次数；缺失的译文、图表或文本不会因读取请求而现场生成。
