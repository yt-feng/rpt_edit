# 摩根大通：中国AI开源权重策略，分布优势与付费转化路径

开源权重商业化策略：赢家通吃；上调智谱至 2,000 港元，下调 MiniMax 至 300 港元（中性）

读者通常将开源权重发布视为变现漏损，因为公开权重允许第三方在自有 API 路径之外部署模型。我们同意这一观点，但我们认为更关键的问题是，大语言模型提供商能否将降低的访问控制转化为更广泛的分布和付费转化。在我们看来，答案很大程度上取决于模型能力——对于有竞争力的模型，开源权重可以在 CSP、推理平台和私有部署的外部 GPU 算力上扩大采用，而不仅仅局限于提供商自身的计算堆栈。大语言模型提供商仍可通过官方支持的路径、许可授权、市场 SaaS、收入分成、部署支持或企业联合销售来参与并变现，尤其是在客户关注模型新鲜度、端点质量和可靠性时。对于较弱的模型，降低访问控制可能导致更快的价格比较和流量重定向。这对智谱是利好，因为 GLM-5.2 具有全球竞争力定位，而对 MiniMax 则更具挑战性，因为 M3 尚未展现出足够的差异化和定价能力。因此，开源权重商业化正演变为一个“赢家通吃”的框架。

- 合作伙伴渠道（如 CSP 和推理平台）仍有动力与开源权重的大语言模型提供商合作，因为商业客户购买的是生产级模型服务，而不仅仅是权重访问权限。公开发布更接近一个起始检查点，而官方路径则可通过发布后的模型更新和服务优化持续改进。如果第三方部署落后于官方路径，相同的模型名称在不同端点可能带来截然不同的用户体验。对于更强的模型，客户需求使得合作伙伴渠道更有理由支持官方授权的访问，即使自行部署能提供更好的毛利率。这使得模型提供商能够在外部算力的宏观环境活动中保持角色。

- 近期的发布符合这一框架。智谱的 GLM-5.2 发布看起来是一个更自信的开源权重策略：通过宽松的访问权限扩大采用，同时将官方路径和更高服务变体（如 GLM-Turbo 系列）定位于对质量敏感的需求。MiniMax 采取了类似策略，保持模型开源并附加额外的商业化限制，然而，我们认为关键问题在于模型竞争力。如果用户认为模型是可替代的，开放访问使其更容易被比较、路由和替换；如果模型强大，开放访问则扩大覆盖范围并创造更多回归付费使用的路径。从企业用户的角度看，开源权重还可以降低采用和可访问性不确定性，因为如果托管 API 的定价、访问策略或可用性发生变化，用户有备用路径。

- 我们认为这一框架为智谱提供了可观的期权价值，而收入路径仍取决于持续的模型领先地位。在当前估值下，我们认为市场已基本消化了公司 10 亿美元的年化经常性收入指引，而更广泛的开源权重变现路径尚未被充分反映。关键考验在于：GLM-5.2 是否代表了公司层面的能力跃升，Kimi K3 和 DeepSeek V4.1 与之相比如何，以及 GLM-5.5/6 能否扩大差距。。对于 MiniMax，近期发布在这一框架下提供的模型驱动定价能力和付费转化证据较弱——我。

## 开源权重策略：分布优势、模型访问不确定性与更灵活的变现策略

开源权重策略一直是中国大语言模型市场的重要组成部分，我们认为读者的争论更集中于这些大语言模型提供商如何利用开放分布来构建可变现的渠道。我们认为其商业逻辑是利用开放访问更快地触达开发者、云平台、API 聚合商和海外用户，然后通过官方 API、云合作伙伴关系、企业部署和工作流产品实现变现。

这种开源策略的成本也显而易见：一旦模型开源权重，云服务提供商、API 聚合商和技术能力强的企业就可以将其部署在自己的基础设施上。这为原本可能流向大语言模型提供商自有 API 的部分流量创造了竞争。这种不确定性在简单工作负载中最为明显，例如聊天、摘要、翻译、基础问答和其他低服务等级协议的文本任务，这些任务中用户主要比较价格和基本功能。这些任务对模型新鲜度、长上下文稳定性、工具调用、提示缓存和企业支持的要求较低。

尽管如此，开源权重并不会使所有 API 端点等同。运行一个开放模型与运营一个高质量的生产推理服务是不同的。第三方部署可能更便宜或更广泛可用，而自有 API 通常能更好地访问最新模型版本、模型特定的服务参数、提示缓存、长上下文执行、速率限制管理、工具链支持和企业 SLA。对于要求更高的工作负载，专有 API 的定价与稳定访问更高质量的端点相关联。

在模型初始发布后，质量差距可能扩大。开源权重发布通常是一个已发布的检查点，而官方 API 则是一个持续更新的产品。发布后，模型提供商继续观察真实流量并优化模型、系统层和服务堆栈。这些后续改进可能包括后训练更新、指令遵循优化、编码和工具使用调优、拒绝策略变更、路由逻辑、缓存策略、上下文窗口处理、解码参数和推理内核优化。这些更改中的大部分不会实时重新开源。因此，即使原始基础权重相同，同一开源权重模型的第三方部署在感知智能和生产可靠性方面可能逐渐落后于官方 API。

这对于编码、代理和长上下文工作负载尤其相关。在这些任务中，用户通常关心任务完成度、仓库级理解、调试质量、多步骤规划、工具可靠性和延迟一致性。服务堆栈中的微小差异可能导致用户体验的显著差异。因此，相同的模型名称并不能保证相同的产品质量。

因此，我们认为应将开放权重策略视为收入结构的变化。大语言模型提供商可能会失去部分仅与模型访问相关的收入，但同时会为付费推理、云分发和工作流变现赢得更广阔的市场。这种平衡会因模型质量而异：更强的模型更有可能吸引开发者，获得云平台优先权，并将开放权重的采用转化为付费使用。

## 开放权重是大语言模型提供商的动态商业选择

开源应根据模型版本、许可证和渠道进行分析。大语言模型提供商可以根据模型代际、能力层级、客户类型和商业化阶段，决定开放哪些模型、许可证的宽松程度，以及将哪些高级版本保留在付费渠道中。

2025-26年的发布周期显示，中国主要独立大语言模型提供商呈现出三种普遍模式：DeepSeek最接近宽松的开放权重一端；智谱使用宽松的开放权重基础旗舰模型来推动采用，同时将精选的Turbo/多模态Turbo变体保留在托管API渠道中；Kimi和MiniMax展示了修改版或社区许可证如何保留不同程度的商业控制权。

对于用户而言，开放权重路线创造了一个备用选项。一旦权重公开，开发者和企业可以自行部署、使用第三方推理提供商，或在托管访问发生变化时跨云迁移。这种访问确定性可以支持实验和生态系统建设。它还能减少用户对模型系列可能因政策变化、访问限制或商业纠纷而从其技术栈中消失的担忧。

## API质量：专有API销售的是对更新、更高质量模型的稳定访问

开放权重发布增加了模型的可获得性，但这并未使API产品变得可互换。在生产环境中，用户购买的是服务路线，而不仅仅是模型权重。该路线包括模型新鲜度、缓存策略、吞吐量、延迟、功能支持、可靠性和提供商级优化。我们认为，专有API对大多数用户来说仍然是最优选择，因为它们提供了获取最新、最高质量模型变体的最稳定途径，而第三方部署虽然能扩大访问范围，但其宏观环境性和服务质量更具波动性。

模型新鲜度日益重要。开放权重模型应被视为一个已发布的检查点，而官方API则是一个持续优化的产品。发布后，模型提供商可以根据实时流量不断改进指令遵循、编码行为、长上下文稳定性、工具调用、拒绝策略、缓存策略和推理效率。这些优化通常会被吸收到官方端点中，而无需完全公开重新发布权重。对用户而言，官方API可能表现得像是同一模型的更新、更强大的版本，而第三方端点可能仍在运行早期的开放权重快照或优化程度较低的服务栈。

数据指向了第一方API优势的两种形式。DeepSeek V4 Pro是价格驱动的案例：在重复上下文的负载下，官方路线比选定的第三方路线便宜约6-12倍，这得益于更低的标价和更强的缓存宏观环境性。MiniMax M3则展示了质量驱动的案例：各提供商的标称输出定价大致相似，但官方路线具有更高的缓存命中率、更低的实际输入成本、更高的使用集中度和更强的速度。这些案例表明，开放权重分发可以扩大覆盖范围，而不会完全商品化第一方API收入。

案例研究 #1：DeepSeek V4 Pro – 官方路线通过标价和缓存宏观环境性取胜

DeepSeek V4 Pro是第一方API以价格作为护城河的最清晰例子。OpenRouter的提供商级数据显示，DeepSeek官方路线的有效输入定价远低于选定的第三方路线，缓存命中率也更高，而在缓存生效前，模型级价格也具有优势。在一个简化的月度工作负载中（1亿有效输入Token和2000万输出Token），官方路线的成本约为24-41美元，而选定的第三方路线成本为85-196美元。这种差距对于编码代理、检索增强生成（RAG）和长上下文自动化尤其重要，在这些场景中，重复的系统提示、仓库上下文、工具模式和中间状态使得缓存效率成为实际成本的主要驱动因素。我们认为，这种有效定价比标价更有意义，因为它反映了客户在提示缓存后实际支付的费用，而重复上下文可以使实际成本显著低于标称标价。

同样的逻辑也适用于价格之外。如果DeepSeek在开放权重发布后继续优化官方端点，那么官方API可以保持一个仅从模型名称无法完全体现的质量优势。第三方提供商可能宣传相同的模型系列，但随着官方路线整合了更多发布后的调优，用户仍可能在答案质量、工具可靠性、缓存行为、延迟一致性和长上下文完成度方面看到差异。

## CSP 与推理平台分发：利润率留存与模型质量之间的权衡

开放权重为海外云和推理平台提供了更多选择，但商业抉择依然相同：它们可以自行部署模型并保留更多 API 宏观环境收益，或者与模型提供商更紧密合作，放弃部分宏观环境收益以换取更好的版本同步、技术支持和端点质量。我们认为，这种利润率与质量的权衡是 LLM 分发下一阶段的核心，尤其是在中国开源权重模型进入 AWS、Azure/Foundry、Cloudflare 和 OpenRouter 等全球平台之际。

对于 CSP 和推理提供商而言，自行部署路径在宏观环境上具有吸引力。一旦权重开放，平台可以在其自有基础设施上部署模型，自行定价，通过自有堆栈路由流量，并获取更高的毛利率。这种模式最适合稳定模型、通用文本任务和对价格敏感的流量。其代价是服务质量成为平台的责任。平台需要管理模型更新、量化、批处理、上下文处理、缓存行为、可靠性和客户支持。一个糟糕的部署可能使同一模型感觉比官方端点更慢、更不稳定或能力更弱。

自行部署还伴随着模型维护不确定性。一旦模型权重开放，平台可以在其自有基础设施上部署，但也需要负责量化、批处理、缓存策略、内核优化、模型更新、安全层和面向客户的可靠性。如果模型提供商持续改进官方 API，但未将每一次后续变更都发布到公开权重中，那么自行部署的端点可能会变得陈旧。这就是为什么利润率留存决策不仅仅关乎图形处理单元（GPU）成本。平台也在选择其愿意承担多少模型新鲜度和质量控制负担。

对于高价值工作负载而言，合作路径更具吸引力。平台可以通过官方提供商身份、许可、收入分成、技术支持、市场软件即服务（SaaS）分发或企业联合销售等方式与模型提供商合作。这会降低平台的抽成比例，同时提升模型新鲜度、服务指导、企业信任和支持。我们预计，这条路径对于前沿或接近前沿的模型、编码和智能体工作负载、长上下文 API 以及企业生产部署将更为常见，在这些场景中，客户更关心任务完成度和可靠性，而非表面的 Token 价格。

近期的全球分发实例支持了这一框架。在 AWS 上，GLM 5 作为 Bedrock 托管模型提供，而 GLM-5.2 则通过 AWS Marketplace 作为 Z.AI 的 SaaS API 产品提供。Bedrock 让 AWS 对托管模型体验拥有更多控制权，而 Marketplace 则保留了 Z.AI 更多的第一方 API 关系和版本控制。在 Azure 上，Microsoft Foundry 通过 Fireworks AI 分发特定的中国开源模型（包括 GLM5.2）；企业客户通过 Azure 接入，但 Fireworks 充当推理提供商。Fireworks 同样面临这一权衡：它可以通过自行优化和服务开源模型来保留更多宏观环境收益，但端点质量取决于其能否跟上模型版本、服务配方和工作负载特定优化的步伐。

在这些模型之间的选择应保持动态。一个迭代速度快、基准测试领先明显且客户吸引力强的模型，更有可能保留第一方或官方支持的变现方式，因为平台需要更新的版本、官方支持和更好的服务配方来满足用户期望。一个较旧、更稳定或差异化较小的模型，则更有可能被 CSP 和推理提供商自行部署，因为客户可能优先考虑价格和可用性，而非边际质量差异。渠道策略也会随着客户反馈的演变而改变。如果用户报告第三方端点存在质量差距，流量可能会回流至官方 API 或官方支持的部署；如果第三方提供商以更低成本提供可比质量，更多流量可能会转向 CSP、推理平台或聚合器渠道。

这一框架为 LLM 提供商在权重开放后仍保留了收入空间。CSP 和推理提供商可以绕过模型公司处理某些工作负载，但这样做时，质量和支持责任会上升。在那些采用依赖于可靠性、模型新鲜度、缓存宏观环境性和任务完成度的工作负载中，官方 API 和官方支持的端点应保持商业相关性。开放权重扩大了分发范围，而最佳的变现路径则取决于模型质量、迭代速度和客户使用模式。

对于中国 LLM 提供商而言，海外云分发仍应是积极的。它降低了客户获取成本，扩大了全球覆盖范围，并允许使用量在第三方基础设施上扩展。其代价是在某些渠道中直接控制力减弱且需共享宏观环境收益。对于强大的模型，我们认为这是一个可接受的漏斗：用户可能从 CSP 目录、市场、Fireworks 风格的推理层或聚合器开始，然后在可靠性和支持变得更重要时，迁移至第一方 API、高级端点或工作流产品。

## 工作流：专有框架可将开源权重采用转化为更具粘性的 API 使用

目前，API 访问仍是 LLM 提供商的主要商业化路径。这是将模型能力转化为收入的最直接方式，尤其适用于不需要模型公司提供完整产品层的开发者工作负载、企业集成和第三方应用。我们预计，短期内 API 收入仍将是大多数 LLM 提供商的核心收入来源，但展望未来，更关键的问题在于，随着模型能力扩散和开源权重替代方案增多，定价权能在何处得以维持。

我们预计 API 定价将日益分化。成熟智能的价格应随时间下降，简单的聊天、摘要、翻译和基础问答更容易被复制、评估，用户也更容易在不同提供商之间切换——在这些工作负载中，客户会比较有效成本、延迟和稳定性，一旦输出质量足够好，成本更低的提供商可以迅速获得市场份额。前沿智能遵循不同的定价逻辑：当一个模型在编码、智能体执行、长上下文推理或高可靠性企业工作流中创造出明显差距时，用户可以接受更高的 API 价格，因为该模型改变的是任务完成度，而不仅仅是 Token 成本。这就是为什么即使成熟能力变得更便宜，前沿能力的提升仍能支撑定价权（详见我们之前的报告《智谱AI：成熟智能压低定价，但 GLM-5.2 显示前沿升级可反其道而行之》）。

这种分化也解释了为什么大语言模型（LLM）提供商正试图超越原始API销售。一家仅通过第三方渠道销售Token的公司，仍然面临流量被重新路由的不确定性。当另一个模型变得更便宜或达到类似能力时，云端点、人工智能集成开发环境（AI IDE）或智能体平台可以迅速转移流量。因此，LLM提供商有强烈的动机围绕自身模型构建专有工具。这些产品将模型从可替换的后端转变为用户日常工作流程的一部分。智谱的Z Code、MiniMax的MiniMax Code、Kimi的Kimi Code实验以及DeepSeek围绕智能体工具岗位的招聘，都指向同一个方向：LLM提供商正试图掌控更多的使用层，而不是将客户关系完全交给云、IDE和应用平台。

这对于开放权重模型的变现尤为重要。如果用户仅通过第三方云、API路由器或外部IDE访问开放模型，LLM提供商可能会获得知名度，但无法拥有客户关系。当同行模型变得更便宜或足够好时，流量可以迅速被重新引导。一个成功的自有工具改变了这一等式：开放权重可以在漏斗顶部扩大采用，而提供商自身的编码智能体、工作流产品或企业工具则将部分采用转化为粘性的自有使用。在这种情况下，开源对客户粘性和专有API销售的谨慎影响较小，因为用户不再是在可比较的端点之间进行选择。用户是在围绕提供商自身模型设计的产品层内工作。

专有工具的战略价值大于增量订阅收入。如果用户通过提供商自身的编码智能体或工作流产品消费模型，模型公司将获得直接的用户关系、更快的反馈循环、更多的专有使用数据以及更强的留存率。它还可以使API使用更具锁定性。提供商无需在通用Token定价上竞争，而是可以将模型与仓库索引、上下文管理、工具调用、记忆、权限、调试循环、企业控制和工作流特定优化打包在一起。客户随后为任务完成度和可靠性付费，而Token消耗则嵌入在更广泛的工作流产品中。

美国编码智能体市场提供了一个有用的参考。Cursor成为许多开发者的首选工作流层，因为它将强大的编码界面与对领先模型的访问相结合。Claude Code的出现表明，当底层模型具有足够差异化时，LLM提供商可以将使用拉回自身环境。对许多开发者而言，最初使用第三方编码工具的原因是访问当时最好的编码模型。一旦Anthropic将强大的Claude模型与围绕这些模型优化的自有编码工具配对，一些高级用户就有了将更重的智能体编码工作转移到Claude Code的理由。更广泛的教训是，当LLM提供商能够提供卓越的模型能力和更好的模型特定工具时，工作流的所有权是可以争夺的。

我们认为，这种迁移的发生需要两个条件。第一个是持续的模型领先地位。用户需要一个明确的理由来改变他们现有的工作流，而这个理由通常始于模型质量。在编码领域，差距需要体现在仓库级理解、多步调试、长程规划、工具使用和完成率上。一个仅略好的模型可能会赢得基准测试的关注，但可能不会改变开发者的日常行为。一个明显更好的模型可以成为用户首先打开一个产品的理由。如果开发者使用第三方IDE主要是为了访问一个模型系列，那么LLM提供商就有一条可信的路径，将部分使用拉入其自身的工具。

第二个条件是工具特定的优化。一个自有工具需要让提供商自身的模型比同一个模型在第三方包装器中工作得更好。这需要在上下文工程、仓库索引、记忆、工具执行、权限设置、测试循环、错误恢复和产品用户体验（UX）方面进行高频迭代。当模型团队和产品团队共同优化时，优势会叠加。模型可以针对工具进行调优，而工具可以围绕模型的优势和失败模式进行重新设计。随着时间的推移，自有产品可以不仅仅是一个分发渠道。它成为模型有效能力的一部分。

中国的迁移路径可能比美国参考案例更困难。腾讯元宝、字节跳动Trae和阿里Qoder已经在意掌控工作流入口，并通过现有流量、生态系统关系和产品分发积累了早期用户。中国的LLM提供商还面临一个更拥挤的模型格局，其中领先者之间的能力差距通常比美国最强前沿模型与市场其他模型之间的差距更窄。这使得任何单一模型公司更难仅凭适度的模型改进来说服用户离开现有的工作流产品。

在中国，自有工具的采用仍然是可能的。关键变量在于LLM提供商能否创造出绝对的能力阶跃变化。如果一个中国模型在编码或智能体工作流方面变得明显更强，并且提供商自身的工具能够持续地将这种模型优势转化为比使用相同API的第三方平台更好的任务完成度，那么用户行为是可以改变的。在这种情况下，LLM提供商将拥有一条超越通用API访问的路径。它可以拥有一个更高价值的工作流层，提高客户留存率，使使用更具专有性，并减少在成熟Token市场中对价格竞争的依赖。

## 公司观点：SOTA模型应能捕获开放权重变现的大部分上行空间

来自开放权重模型的收入机会应保持集中。开放权重扩大了分发，但变现仍然取决于模型质量、迭代速度、端点可靠性、工作流附着度和企业信任。更强的SOTA或接近SOTA的模型更有可能获得开发者采用，获得CSP和第三方推理平台的优先权，保留官方支持的API宏观环境性，并将使用转化为工作流产品。较弱的模型仍然可以产生下载和实验，但当模型在任务完成度上没有创造可见差异时，付费转化则更加困难。

开放权重也降低了用户对访问连续性的担忧。公开权重模型为开发者和企业提供了一条备用路径，以防托管端点变更政策、提价或不可用。这种访问确定性有助于推动采用、实验和生态建设。然而，货币化的上行空间仍取决于提供商能否使其官方API、云合作伙伴关系和工作流产品明显优于备用的开放权重路径。

随着市场变得更加开放，这种集中度问题愈发重要。一旦权重公开，用户和平台可以更快地比较模型。一个仅仅是可用或便宜的模型可能在通用工作负载中被使用，但当另一个模型变得更便宜或足够好时，它更容易被替代。一个在编程、智能体执行、长上下文推理或企业可靠性方面明显更优的模型，拥有更多变现途径：第一方API、官方支持的部署、云市场、企业部署和专有工具。这就是为什么我们预计开放权重的玩法将更多地奖励能力领先者，而非参与者。

关键问题在于定价能力。强模型可以利用公开权重扩大采用，然后通过官方路线、合作伙伴支持的端点、企业部署和工作流产品实现变现。差异化程度较低的模型则面临更快的价格比较和更容易的流量重路由，这些流量会在第一方API、聚合器、云服务商路线和私有部署之间转移。因此，M3的永久性50%折扣是一个重要信号，表明该模型尚未相对于国内领先同行获得能力溢价。折扣可能支持短期使用量，同时降低对模型驱动变现的信心。

MiniMax的开放权重策略仍能创造分发价值，尤其是考虑到其多模态产品组合和海外开发者曝光度。MiniMax Code在方向上与向工作流所有权的转变一致，即第一方产品可以建立直接的客户关系，并使API使用更具粘性。挑战在于，工作流变现需要更强的模型吸引力。一个编程或智能体产品需要足够改进任务完成度以改变用户习惯，而不仅仅是提供另一个访问广泛可用模型的途径。

下一次模型发布是关键催化剂。如果MiniMax缩小与国内领先者的能力差距、在折扣正常化后维持API使用量、改善工作流采用率，并展现出更清晰的模型驱动定价证据，我们将转为更积极的态度。在此之前，我们认为，为智谱创造上行选择权的同一开源权重力量，给MiniMax带来了更多不确定性：更广泛的分布、更快的价格比较以及更弱的维持溢价宏观环境的能力。
